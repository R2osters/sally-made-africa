# Audit 360° — TravelConnect (2026-07-04)

Intent : bilan de santé avant le sous-projet Auth (rescue-and-continue). Poids fort : continuité, delivery, architecture.

## Verdict

Le code livré est sain : architecture feature-first propre, 13/13 tests verts, `flutter analyze` sans warning, design system cohérent, aucun secret commité, handoff exemplaire. Le vrai danger n'est pas dans le code — il est autour : **le projet n'existe que sur un seul disque local (aucun remote, aucun backup)**, le worktree principal `D:\Sally made africa` est dans un état git cassé (160 suppressions stagées sur la branche `auth`), et **deux lignées de développement divergentes coexistent** (la refonte UI mergée sur `main` vs une branche parallèle non mergée de 24 commits contenant déjà catalog + purchase en mock). Le plus gros atout : la discipline de process (specs, plans TDD, HANDOFF.md) et la réponse au point aveugle « provisioning » qui dort dans `esim-integration/` sans être intégrée.

## Constats critiques

**C1 — Perte totale possible (existentiel).** Pas de remote git. Tout le projet — code, specs, plans, historique — vit sur `D:\` uniquement. Panne disque = projet mort.

**C2 — Worktree principal cassé.** `D:\Sally made africa` est checkout sur la branche `auth` avec **160 fichiers en suppression stagée** (tout l'arbre tracké) + 20 entrées non trackées (les mêmes fichiers, présents sur disque). Un `git commit` là-bas committerait la destruction de l'arbre sur `auth`. Toute session future qui démarre dans ce dossier hérite de la confusion.

**C3 — Deux lignées divergentes.** `main` (= `0afcc48`, refonte UI mergée) vs `assistant/intelligent-rhodes-769ba5` (24 commits non mergés : splash, onboarding, auth mock, **catalog avec schéma Supabase Country/EsimPlan + seed**, **purchase flow complet en mock**). Travail dupliqué, incompatible avec la lignée mergée. Décision requise : moissonner (schéma catalog, patterns purchase) puis supprimer, ou tout jeter.

**C4 — Spec Auth périmée.** `auth` (`a3df9e7`) contient spec + plan TDD Auth écrits contre le code pré-refonte. Les écrans Auth UI existent maintenant. Exécuter ce plan tel quel casserait ou dupliquerait l'existant.

**C5 — Décision provisioning non actée.** `esim-integration/` (non tracké) répond au point aveugle bloquant identifié avant Purchase : eSIM via chaîne LPA, `EuiccManager` (Android) / `CTCellularPlanProvisioning` (iOS), **backend Node** qui parle à l'agrégateur. Ce backend Node contredit l'hypothèse Supabase-only. Décision d'architecture à prendre avant de figer Auth/Purchase.

## Quick wins (≤1 jour chacun)

1. **Remote GitHub privé + push de toutes les branches** — supprime C1. ~30 min.
2. **Réparer le worktree principal** : `git reset` (les fichiers sont sur disque, rien à perdre), remettre sur `main` proprement — supprime C2. ~30 min. Précaution : les branches sont détenues par des worktrees, vérifier avec `git worktree list` avant.
3. **Purger** : 6 branches `assistant/*` pointant sur des commits déjà dans `main`, 2 zips à la racine, dossier `build/`. ~15 min.
4. **Tracker `esim-integration/`** dans `docs/` (c'est de la doc d'intégration, pas du code actif). ~10 min.
5. **Dettes mineures** : garde `loaded` dans `theme_provider.dart` (dette #2 devenue active depuis que le toggle Profile est câblé), rename `anonKey` → `publishableKey`, cast inutile. ~1 h avec tests.

## Annexes

### Sécurité (assessment, pas de fix)
- Scan secrets `lib/ + test/` : négatif (aucune URL supabase réelle, aucun JWT, aucune clé).
- Creds via `--dart-define` avec placeholders par défaut : correct pour ce stade.
- Pas de réseau actif, pas d'auth réelle, pas de PII : surface quasi nulle aujourd'hui. Les exigences (secure storage, biométrie, guards invités) arrivent avec le sous-projet Auth — item #6.
- `esim-integration` : `ESIM_API_KEY` prévu en variable d'env côté backend, correct.

### Détails techniques
- `flutter analyze` : 2 issues info — `deprecated_member_use` sur `anonKey` ([supabase_client.dart:10](lib/core/config/supabase_client.dart)), `unnecessary_cast` (test, volontaire).

- Deps : 60 packages transitifs ont des versions majeures plus récentes (normal, contraintes Flutter) ; directes toutes récentes.
- `theme_provider.dart` : `_loadPersisted()` non attendu depuis `build()` ; le toggle Profile étant câblé, un toggle utilisateur dans la première seconde peut être écrasé par la lecture persistée. Garde à ajouter.
